# 03 标准组件开发流程

写组件最容易犯的错，是需求没想清楚就让 AI 开始写。

下面这套流程适用于简单组件，也基本符合公司组件库的工作方式。

## 第一步：先写组件说明，不写代码

以 `StatusTag` 为例：

```text
用途：展示成功、警告、失败状态。
内容：默认显示 text，也允许默认插槽替换。
属性：text、type、plain、disabled。
事件：click。
状态：默认、禁用、点击。
```

如果这几行写不出来，说明需求还不清楚。

## 第二步：设计组件 API

| 名称 | 类型 | 默认值 | 作用 |
|---|---|---|---|
| `text` | `string` | `''` | 标签文字 |
| `type` | `'success' \| 'warning' \| 'error'` | `'success'` | 标签状态 |
| `plain` | `boolean` | `false` | 是否空心 |
| `disabled` | `boolean` | `false` | 是否禁用 |

事件也要列出来：

| 事件 | 参数 | 触发时机 |
|---|---|---|
| `click` | `MouseEvent` | 非禁用状态被点击 |

这张表就是组件的合同。代码只是实现合同。

## 第三步：先做最小结构

```vue
<template>
  <span class="status-tag">
    <slot>{{ text }}</slot>
  </span>
</template>
```

先确认结构正确，再加属性、事件和样式。

## 第四步：加入 props 和默认值

```vue
<script setup lang="ts">
type Status = 'success' | 'warning' | 'error'

interface Props {
  text?: string
  type?: Status
  plain?: boolean
  disabled?: boolean
}

const props = withDefaults(defineProps<Props>(), {
  text: '',
  type: 'success',
  plain: false,
  disabled: false,
})
</script>
```

默认值应该符合最常见的使用场景。

## 第五步：处理 class 和状态

```vue
<span
  class="status-tag"
  :class="[
    `status-tag--${props.type}`,
    { 'status-tag--plain': props.plain, 'is-disabled': props.disabled },
  ]"
>
  <slot>{{ props.text }}</slot>
</span>
```

不要把所有判断塞进一个超长表达式。状态复杂时，改用 `computed` 计算 class。

## 第六步：处理事件

```ts
const emit = defineEmits<{
  click: [event: MouseEvent]
}>()

function handleClick(event: MouseEvent) {
  if (props.disabled) return
  emit('click', event)
}
```

组件内部先处理自己的规则，再通知外部。

## 第七步：写样式

建议顺序：

1. 基础布局。
2. 尺寸和间距。
3. 文字和颜色。
4. 不同状态。
5. hover、active、disabled。

公司项目有 `design-system`，正式组件优先使用设计变量，不要到处写死颜色。

## 第八步：写演示页面

至少展示：

- 默认状态。
- 每种类型。
- 禁用状态。
- 边界情况，例如超长文字、空内容。
- 事件是否触发。

公司项目的组件演示主要放在：

```text
apps/dj-ui-demo/src/views/
apps/dj-ui-demo/src/views/mobile/
```

## 第九步：导出组件

组件写完后，还要在包入口导出：

```ts
export { default as VanStatusTag } from './components/status-tag/index.vue'
export type { StatusTagProps } from './components/status-tag/types'
```

公司移动端组件入口是 `packages/vant-extra/src/index.ts`。

## 第十步：验证

- 页面能否正常显示。
- props 是否真的生效。
- 事件是否只触发一次。
- 禁用状态是否阻止操作。
- `v-model` 能否双向更新。
- 插槽是否正常。
- 控制台是否报错。
- 是否导出组件和类型。
- 格式、构建、测试是否通过。

## 完整流程口诀

```text
明确用途 → 设计 API → 搭结构 → 加数据 → 加事件
→ 写样式 → 写 demo → 导出 → 测试
```

先把简单版跑通，再增加功能。不要第一次就追求“完美组件”。
