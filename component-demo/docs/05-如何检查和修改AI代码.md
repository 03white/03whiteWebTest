# 05 如何检查和修改 AI 代码

AI 可以帮你写代码，但不能替你决定需求，也不知道公司所有约定。

正确方式是：**让 AI 写小块，你负责验收。**

## 提问前先给清楚五件事

```text
1. 技术栈：Vue 3 + script setup + TypeScript。
2. 组件用途：解决什么问题。
3. API：props、事件、插槽、v-model。
4. 项目约束：命名、目录、设计变量、是否包装 Vant。
5. 输出范围：一次只生成哪些文件。
```

## 推荐提示词

```text
请为 Vue 3 + TypeScript 项目实现一个 StatusTag 组件。

要求：
1. 使用 <script setup lang="ts">。
2. props：text、type、plain、disabled。
3. type 只能是 success、warning、error，默认 success。
4. 支持默认插槽，插槽内容优先于 text。
5. 非 disabled 时点击触发 click 事件。
6. 使用 scoped SCSS。
7. 先给出 API 表和实现思路，等我确认后再写代码。
8. 不添加需求之外的功能。
```

关键点是最后两条：先讲方案、不要擅自加功能。

## AI 代码的七项检查

### 1. 需求有没有做偏

检查 props、事件、插槽是否与 API 表一致。没有需求的功能就删除。

### 2. props 有没有被直接修改

错误：

```ts
props.modelValue = 'new value'
```

正确：

```ts
emit('update:modelValue', 'new value')
```

### 3. v-model 是否完整

必须同时有 `modelValue` 和 `update:modelValue`。

### 4. 事件是否重复触发

模板已经 emit，函数中又 emit 一次，会导致一次点击触发两次。

### 5. 禁用状态是否只有样式，没有行为

只把颜色变灰不够。禁用时通常还要阻止点击、输入或清空。

### 6. 是否破坏第三方组件能力

包装 Vant 或 Element Plus 时，检查：

- 是否透传必要的 `$attrs`。
- 是否继续传递插槽。
- 是否错误覆盖原组件 props。
- 是否依赖了不稳定的内部类名。

### 7. 是否忘记出口和 demo

常见漏项：

- `src/index.ts` 没导出。
- 类型没有导出。
- demo 没有入口。
- 样式文件没有引入。

## 看不懂 AI 代码时怎么问

不要问：“解释一下这段代码。”范围太大。

一次只问一个问题：

```text
这段 computed 依赖哪些数据？什么时候重新计算？
```

```text
为什么这里不能直接修改 props.modelValue？
```

```text
请画出这个组件 v-model 的数据流，不要重写代码。
```

```text
请列出删除这段代码会影响哪些功能。
```

```text
请把这段函数逐句翻译成大白话，每句不超过 20 字。
```

## 修改 AI 代码的安全方法

1. 修改前先确保当前版本能运行。
2. 一次只改一个功能。
3. 每改一次就刷新页面或运行测试。
4. 出错时先看第一条错误。
5. 不确定的代码先注释，不要一次删除一大片。
6. 用 Git 查看改动，确认没有误改其他文件。

## 让 AI 做代码审查

```text
请只审查，不要重写整个组件。

按下面顺序检查：
1. props 类型和默认值；
2. emit 和 v-model；
3. slot 和 attrs 透传；
4. disabled 等边界状态；
5. 是否有重复状态或无用代码；
6. 是否符合当前目录中其他组件的写法。

每个问题说明：位置、原因、最小修改方案。
```

## 最低验收标准

即使代码由 AI 生成，你也必须能说清：

- 每个 prop 为什么存在。
- 每个 emit 在哪里触发。
- 每个 ref 保存什么。
- 每个 computed 根据什么计算。
- 删除某段代码会坏掉什么。

如果说不清，就先不要提交到公司项目。
