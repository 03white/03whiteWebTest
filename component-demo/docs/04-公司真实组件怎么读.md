# 04 公司真实组件怎么读

不要从最复杂的组件开始读。建议按 `Tag → Button → Input` 的顺序。

## 第一层：Tag，只改样式的封装

源码位置：

```text
D:\Project\web\web-vue3-ui-dj\packages\vant-extra\src\components\tag\index.vue
```

核心结构可以简化成：

```vue
<script setup lang="ts">
import { Tag as VanTagRaw } from 'vant'

defineOptions({ name: 'VanTag', inheritAttrs: false })
</script>

<template>
  <VanTagRaw class="dxq-mobile-tag" v-bind="$attrs">
    <!-- 继续传递所有插槽 -->
  </VanTagRaw>
</template>
```

大白话解释：

- `VanTagRaw` 是 Vant 原来的标签。
- 新组件没有重新造标签，只给它套上公司主题样式。
- `v-bind="$attrs"` 把外部属性和事件继续交给 Vant。
- 遍历 `$slots` 是为了把 Vant 原有插槽继续开放给使用者。
- `inheritAttrs: false` 表示由代码决定属性最终传给谁。

要学的是这个思想：**能包装就不要重写。**

## 第二层：Button，增加公司自己的能力

源码位置：

```text
D:\Project\web\web-vue3-ui-dj\packages\vant-extra\src\components\button\index.vue
D:\Project\web\web-vue3-ui-dj\packages\vant-extra\src\components\button\types.ts
D:\Project\web\web-vue3-ui-dj\packages\vant-extra\src\components\button\index.scss
```

它比 Tag 多了：

- `variant`：公司定义的按钮外观。
- `size`：公司定义的尺寸。
- `danger`、`circle`、`square`：附加状态。
- `withDefaults`：给 `size` 设置默认值。
- `computed`：根据 `variant` 合并要传给 Vant 的属性。
- 动态 class：根据 props 切换样式。

阅读顺序：

1. 先看 `types.ts`，确认对外开放什么。
2. 再看模板，确认 props 如何变成 class。
3. 再看 `computed`，确认属性为什么要转换。
4. 最后看 SCSS，确认 class 对应什么视觉效果。

不要一开始逐行看全部 SCSS。先知道“哪个状态对应哪个 class”，再查具体样式。

## 第三层：Input，自研交互组件

源码位置：

```text
D:\Project\web\web-vue3-ui-dj\packages\vant-extra\src\components\input\index.vue
D:\Project\web\web-vue3-ui-dj\packages\vant-extra\src\components\input\types.ts
```

它涉及：

- `modelValue` 和 `update:modelValue`：实现 `v-model`。
- `ref`：记录是否聚焦、保存原生 input 节点。
- `computed`：计算字数、是否显示清空按钮。
- `focus`、`blur`、`input`、`clear`：处理交互事件。
- props、events、slots、attrs：完整组件通信。
- 组合已有的 `VanButton`：复用其他组件。

先画数据流：

```text
父组件的值
  ↓ modelValue
VanInput 显示值
  ↓ 用户输入
emit('update:modelValue', 新值)
  ↓
父组件更新值
```

只要数据流画清楚，代码就不会像一团线。

## 阅读源码的固定问题

1. 它是完全自研，还是包装 Vant/Element Plus？
2. 它有哪些 props，默认值是什么？
3. 它发出哪些事件？
4. 它支持哪些插槽？
5. 它有哪些内部状态？
6. 哪些结果由 computed 算出？
7. attrs 最后传给了哪个真实元素？
8. 样式状态由哪些 class 控制？
9. 它在哪里导出？
10. demo 覆盖了哪些用法？

能回答这十个问题，就已经基本读懂一个组件。

## 第一遍可以跳过什么

可以先跳过：很长的 SCSS 细节、构建配置、发布脚本、高级泛型和测试配置。

不能跳过：props、emit、v-model、slot、attrs、状态判断和导出。
