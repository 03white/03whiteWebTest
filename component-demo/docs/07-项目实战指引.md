# 07 项目实战指引

这份指引带你在 `training-project/` 中完成第 06 课的所有练习。

## 一、先认识目录

```text
training-project/
├─ package.json                  # 项目命令和依赖
├─ index.html                   # 浏览器入口
├─ vite.config.ts               # Vite 配置
├─ tsconfig.json                # TypeScript 配置
├─ src/
│  ├─ main.ts                   # 启动 Vue
│  ├─ App.vue                   # 练习导航和总页面
│  ├─ style.css                 # 全局样式
│  ├─ components/               # 你要编写的组件
│  │  ├─ StatusDot/
│  │  ├─ StatusTag/
│  │  ├─ CountButton/
│  │  ├─ BaseCard/
│  │  ├─ BaseSwitch/
│  │  ├─ BaseInput/
│  │  └─ AppButton/
│  └─ views/                    # 每个组件的演示页面
│     ├─ StatusDotDemo.vue
│     ├─ StatusTagDemo.vue
│     ├─ CountButtonDemo.vue
│     ├─ BaseCardDemo.vue
│     ├─ BaseSwitchDemo.vue
│     ├─ BaseInputDemo.vue
│     └─ AppButtonDemo.vue
└─ notes/                       # 你自己的复盘笔记
```

大白话理解：

- `components` 是“组件工厂”。
- `views` 是“组件展示台”。
- `App.vue` 是“总目录”。
- `notes` 是“错题本”。

## 二、准备环境

先确认电脑安装了 Node.js 和 pnpm：

```bash
node -v
pnpm -v
```

在 `training-project/` 目录安装依赖：

```bash
pnpm install
```

启动开发服务器：

```bash
pnpm dev
```

终端会出现一个本地地址。按住 `Ctrl` 点击地址，或复制到浏览器打开。

## 三、每次练习的固定流程

### 1. 打开任务

先阅读 `docs/06-动手训练清单.md` 中对应练习，不要先看答案。

### 2. 找到两个文件

每个练习都有：

- 一个组件文件：`src/components/组件名/组件名.vue`。
- 一个演示页面：`src/views/组件名Demo.vue`。

先看演示页面，知道父组件打算怎样使用子组件；再回到组件文件实现功能。

### 3. 先写最小版本

只实现当前任务最核心的一件事。例如 `StatusDot` 先只实现颜色，不要提前加入动画、点击事件或复杂配置。

### 4. 保存并观察浏览器

每改一次就看页面：

- 页面有没有空白。
- 控制台有没有红色错误。
- 传入的数据有没有显示。
- 点击后结果有没有变化。

### 5. 记录错误

在 `notes/` 中新建对应笔记，例如 `notes/01-StatusDot复盘.md`。

不要只记最终答案，要记“我一开始为什么写错”。

## 四、推荐完成顺序

### 第 1 天：静态组件

完成 `StatusDot`、`StatusTag`。

重点掌握：`defineProps`、默认值、动态 class、默认插槽、`defineEmits`。

### 第 2 天：事件和插槽

完成 `CountButton`、`BaseCard`。

重点掌握：`ref`、事件参数、默认插槽、具名插槽。

### 第 3 天：v-model

完成 `BaseSwitch`。

重点掌握：`modelValue`、`update:modelValue`、父子数据流。

### 第 4 天：输入框

按 `6A → 6B → 6C` 完成 `BaseInput`。

重点掌握：原生 DOM 事件、`computed`、清空逻辑、字数统计、focus 和 blur。

### 第 5 天：二次封装

完成 `AppButton`，再阅读公司的 `VanTag`、`VanButton`、`VanInput`。

重点掌握：`$attrs`、插槽透传、包装第三方组件。

## 五、遇到问题时的排查顺序

### 页面空白

1. 打开浏览器开发者工具。
2. 看 Console 的第一条红色错误。
3. 检查组件是否导入。
4. 检查模板标签是否闭合。

### props 没生效

检查父组件属性名字、动态值的 `:`、props 类型和默认值。

```vue
<StatusDot status="success" />
<StatusDot :status="currentStatus" />
```

### 点击没反应

检查 `@click`、函数名、`disabled` 条件，以及是否只改了样式没有写行为。

### v-model 不更新

按顺序检查：

1. 子组件是否接收 `modelValue`。
2. 输入变化时是否 emit `update:modelValue`。
3. 父组件是否真的使用了 `v-model`。
4. 是否直接修改了 prop。

### 样式不生效

检查 class 名、动态 class、`scoped` 和是否错误修改了子组件内部样式。

## 六、如何和 AI 配合

每次只把一个具体问题交给 AI：

```text
我的 BaseSwitch 点击后页面没有更新。
请只根据下面代码画出数据流，并指出最可能的问题。
不要直接重写全部代码。
```

把组件文件、demo 页面和第一条错误一起发给 AI。不要只说“运行不了”，否则 AI 只能猜。

## 七、完成一个练习的验收方式

完成后必须同时满足三项：

### 能运行

页面打开正常，控制台没有错误。

### 能解释

你能用自己的话说明 props、事件、插槽和内部状态。

### 能修改

你能在不让 AI 重写全部代码的情况下，自己完成一个小改动，例如：

- 给 `StatusTag` 增加 `info` 类型。
- 给 `CountButton` 增加初始值。
- 给 `BaseCard` 增加 `bordered`。
- 给 `BaseInput` 增加密码显示切换。

## 八、最终任务

完成七个练习后，独立设计一个 `UserBadge` 组件：

- `name`：名称。
- `avatar`：头像地址，可选。
- `status`：`online | busy | offline`。
- 支持默认插槽替换名称。
- 支持 `click` 事件。
- 支持 `disabled`。

要求：先自己写 API 表，再实现最小版本、demo 和边界测试，最后让 AI 审查，而不是让 AI 从头生成。

做到这里，你就完成了从“看 AI 代码”到“能修改 AI 代码”的第一阶段。
