## props

### 是什么

父组件递给子组件的材料。子组件**只能看，不能改**。

### 不用它会怎样

组件里把文字写死成 `已完成`，这个组件就只会显示"已完成"。想要"处理中"就得复制一个新组件出来。10 种文案 = 10 个组件 = 改一次设计稿要改 10 个文件。

props 的作用就是把"会变的部分"抽出来，让一个组件应对所有情况。

### 最小写法

```ts
const props = defineProps<{ text: string }>()
```

完整语法（含可选属性、默认值）见 [02 的 props 小节](02-Vue组件必会知识.md#props父组件传数据给子组件)。

### 新手最常踩

**1. 想在子组件里改 props**

```ts
props.text = '新的文字'   // 报错
```

props 是父组件的东西，你只是借来显示。要改得让父组件去改 —— 这就是 [emit](#emit-与事件参数) 和 [v-model](#v-model) 存在的原因。

**2. 冒号加错**

```vue
<StatusTag text="已完成" />      <!-- 传字符串"已完成" -->
<StatusTag :text="已完成" />     <!-- 当成变量名去找，找不到 → undefined -->
<StatusTag :text="title" />      <!-- 传变量 title 的值 -->
```

规则：传写死的文字**不加**冒号，传变量**要加**冒号。数字和布尔值也要加冒号 —— `count="1"` 传的是字符串 `"1"`，`:count="1"` 传的才是数字 `1`。

## 联合类型

### 是什么

```ts
type Status = 'success' | 'warning' | 'error'
```

告诉 TypeScript：这个位置**只准填这三个词**。

### 不用它会怎样

如果写成 `status: string`，那么：

```vue
<StatusDot status="sucess" />   <!-- 少了一个 c -->
```

编辑器一声不吭。页面上点变成透明，你对着 CSS 找半小时。

用了联合类型，拼错的那一刻编辑器就画红线，鼠标移上去直接告诉你合法值是哪三个。

### 最小写法

```ts
interface Props {
  status: 'success' | 'warning' | 'error'
}

const props = defineProps<Props>()
```

### 新手最常踩

**1. 以为类型能保证样式存在**

类型只保证"传进来的值合法"，不保证"你写了对应的 CSS"。`status="error"` 合法，但 `.dot--error` 你忘了写，照样没颜色。

**2. 以为运行时也会拦**

TypeScript 只在你写代码和构建时检查，编译成 JS 后类型信息就没了。别人用纯 JS 调你的组件，照样能传任意字符串进来。类型是给人和编辑器看的护栏，不是运行时的保险。

## 默认值

### 是什么

给可选的 props 准备一个兜底值。

### 不用它会怎样

```vue
<StatusTag />
```

什么都不传，`type` 的值是 `undefined`，[动态 class](#动态-class) 拼出来就是 `tag--undefined`，页面上出现一个没有颜色的怪东西。

### 最小写法

```ts
interface Props {
  text?: string
  type?: 'success' | 'warning' | 'error'
  disabled?: boolean
}

const props = withDefaults(defineProps<Props>(), {
  text: '',
  type: 'success',
  disabled: false,
})
```

注意 `?` 和 `withDefaults` 是一对：`?` 表示"可以不传"，`withDefaults` 回答"不传的话用什么"。

### 什么时候该给默认值

问自己一句：**不传这个值，组件还能正常显示吗？**

- 能 → 标上 `?` 并给默认值
- 不能 → 设成必填，**不要**给默认值

硬编一个假默认值（比如 `text: '按钮'`）会让调用方忘了传也不报错，页面上莫名出现"按钮"二字，这种 bug 很难查。

### 新手最常踩

**1. 布尔值的默认值方向**

惯例是 `false`。因为 Vue 里 `<BaseSwitch disabled />` 这种简写等价于 `disabled: true` —— 默认 `false`、需要时简写打开，最顺手。

反过来说，`BaseCard` 的 `shadow?: boolean` 默认是 `true`（大多数卡片都要阴影），这是刻意的例外。代价是关闭它必须写全：

```vue
<BaseCard :shadow="false" />
```

不能写 `<BaseCard shadow="false" />` —— 那传的是**字符串** `"false"`，在 JS 里是真值，阴影照样显示。

**2. 给必填 props 也写了默认值**

等于偷偷把它变成可选，调用方漏传不会报错，白白浪费了类型检查。

## emit 与事件参数

### 是什么

props 是父 → 子，emit 是子 → 父。

子组件喊一声"我被点了"，**父组件决定要做什么**。

### 不用它会怎样

按钮组件自己 `console.log`，或者自己跳转页面 —— 那它就只能用在那一个地方。

把"发生了什么"交给子组件说，"要做什么"交给父组件定，组件才能复用。

### 最小写法

子组件：

```ts
const emit = defineEmits<{
  click: [event: MouseEvent]
}>()

function handleClick(event: MouseEvent) {
  emit('click', event)
}
```

父组件：

```vue
<StatusTag @click="handleClick" />
```

### 为什么要带参数

这是练习 3 的重点。对比：

```ts
emit('change')               // 父组件只知道"变了"，不知道变成几
emit('change', count.value)  // 父组件直接拿到最新数字
```

父组件接收：

```ts
function handleChange(value: number) {
  console.log('最新次数：', value)
}
```

不带参数的话，父组件想知道数字就得自己再存一份 `count`，两边手动同步，迟早不一致。这正是练习 3「故意改坏」第一条要你亲眼看到的。

### 新手最常踩

**1. emit 名和监听名不一致**

子组件 `emit('change')`，父组件写 `@changed` → 永远收不到，而且**不报错**。父组件收不到事件时，先核对这两个名字。

**2. 一次点击收到两次**

模板里 `@click="$emit('click')"`，函数里又 `emit('click')` —— 触发了两遍。练习 3「故意改坏」第三条。

**3. 事件名和原生事件撞车**

子组件根元素是 `<button>`，你又 `emit('click')`：原生点击会冒泡上去，加上你手动 emit 的，父组件可能收到两次。这种情况要么换个事件名，要么别手动 emit。

## ref

### 是什么

会变的数据。包一层 `ref()` 之后，值变了 Vue 才知道要重新画页面。

### 不用它会怎样

```ts
let count = 0
function add() {
  count++      // 数字确实加了
}
```

页面一动不动。Vue 不知道你改了这个变量 —— 它没在"盯着"它。`ref()` 就是请 Vue 盯着。

### 最小写法

```ts
import { ref } from 'vue'

const count = ref(0)

function add() {
  count.value++
}
```

```vue
<template>
  <button @click="add">点击 {{ count }} 次</button>
</template>
```

### 新手最常踩

**1. `.value` 写不写**

- `script` 里**必须**写 `count.value`
- `template` 里**不要**写，直接 `count`

这个不一致是新手最大的坑来源。记法：`ref()` 返回的是个盒子，`script` 里拿到的是盒子（要开盖），`template` 里 Vue 帮你开好了。

漏写 `.value` 时，`count++` 改的是盒子本身，不是里面的数字 —— 页面上会看到 `NaN` 或者纯粹没反应。

**2. 能算出来的值不要用 ref**

字数显示 `3/20` 里的 `3` 是 `props.modelValue.length` 算出来的，用 `computed`：

```ts
const length = computed(() => props.modelValue.length)
```

用 ref 存一份就得在每个改值的地方手动同步，必然漏。规则：**数据只存一份，其他都算出来。**

## v-model

### 是什么

一个语法糖。下面两行**完全等价**：

```vue
<BaseSwitch v-model="enabled" />

<BaseSwitch :model-value="enabled" @update:model-value="enabled = $event" />
```

### 不用它会怎样

也能用，就是每次都要手写两半。练习 5 故意让你先手写两半（第一阶段），再换成 `v-model`（第二阶段），这样你才知道这个糖到底包了什么。

### 最小写法

子组件：

```ts
const props = defineProps<{ modelValue: boolean }>()

const emit = defineEmits<{
  'update:modelValue': [value: boolean]
}>()

function toggle() {
  emit('update:modelValue', !props.modelValue)
}
```

### 新手最常踩

**1. 名字必须一字不差**

`modelValue` 和 `update:modelValue`，错一个字母就不通，而且**不报错**。写成 `modelvalue`、`updateModelValue`、`update:model-value`（在 `defineEmits` 里）都是无效的。

**2. 直接改 props**

```ts
props.modelValue = !props.modelValue   // 错
```

值是父组件的，只能 emit 出去让它改。详见 [受控组件](#受控组件)。

**3. 只接 props 不 emit**

输入框里打不进字、开关点了不动。看起来像组件坏了，实际是：你改了界面，但值没报给父组件，父组件那个没变的值又把界面覆盖回去了。

## 插槽

### 是什么

组件里留个坑，让调用方往里塞**任意内容**。

prop 只能传文字和数据，插槽能传标签、按钮、甚至另一个组件。

### 不用它会怎样

卡片组件只有 `title: string` + `content: string`，那内容里想放一张图、一个表格、一个按钮，全都做不到。

### 最小写法

子组件留坑：

```vue
<template>
  <div class="card">
    <header v-if="$slots.title || title">
      <slot name="title">{{ title }}</slot>
    </header>

    <main>
      <slot />
    </main>

    <footer v-if="$slots.footer">
      <slot name="footer" />
    </footer>
  </div>
</template>
```

调用方填坑：

```vue
<BaseCard title="用户信息">
  <p>卡片内容</p>

  <template #footer>
    <button>确定</button>
  </template>
</BaseCard>
```

### 插槽优先于 prop

练习 2 要求"插槽内容优先于 `text`"。实现只要一行：

```vue
<slot>{{ text }}</slot>
```

`<slot>` 标签**之间**的内容是"没人传插槽时显示的兜底"。所以：塞了插槽就用插槽，没塞就用 `text`。

### 新手最常踩

**1. 具名插槽忘了 `<template #name>`**

```vue
<BaseCard>
  <div>我想当底部</div>          <!-- 掉进默认插槽了 -->
  <template #footer>我才是</template>
</BaseCard>
```

**2. 判断"有没有传插槽"用错东西**

要用 `$slots.footer`，不是 `props.footer`。插槽不是 prop，`defineProps` 里也不用声明。

**3. 不传就该不渲染**

练习 4 完成标准第一条："不传 `title` 时不会显示空标题区域"。做法是上面那个 `v-if` —— 没有 `v-if` 的话，页面上会留一条诡异的空白横条，还带着 padding 和边框。

## scoped

### 是什么

```vue
<style scoped>
.dot { background: green; }
</style>
```

让样式只作用于当前组件。Vue 会给组件里的每个元素偷偷加一个唯一标记，选择器自动带上它。

### 不用它会怎样

你在 `StatusDot` 里写 `.dot { background: green }`，全站**所有**叫 `.dot` 的东西都变绿。项目一大，样式互相污染，改一个地方坏三个页面，而且根本查不出是谁干的。

### 最小写法

加 `scoped` 两个字。就这样。

### 新手最常踩

**1. 以为 scoped 是绝对隔离**

它只管"当前组件自己写出来的元素"。子组件**内部**的元素不带你的标记，所以你改不到。要改子组件内部得用 `:deep()`：

```vue
<style scoped>
.wrapper :deep(.van-button__text) {
  display: flex;
}
</style>
```

`:deep` 能用但别滥用 —— 第三方组件升级后内部类名可能变，你的样式会悄悄失效。

**2. 测试时删了 scoped，忘了加回去**

练习 1「故意改坏」第三条就是让你删掉 scoped 体验污染。体验完记得加回来。

**3. 把"样式不生效"都归咎于 scoped**

更常见的原因是类名拼错或 CSS 里没有那条规则。顺序：先按 F12 看元素身上到底有哪些 class，再看 CSS 里有没有对应规则，最后才怀疑 scoped。

## 动态 class

### 是什么

让元素的 class 跟着数据变，从而让**样式跟着状态变**。

### 不用它会怎样

三种状态就要写三个组件，或者在模板里用 `v-if` 堆三份几乎一样的 `<span>`。加第四种状态时你要改三个地方。

### 三种写法

```vue
<!-- 1. 字符串拼接：状态 → 类名 -->
<span :class="`dot--${status}`" />

<!-- 2. 对象：条件成立才加这个类 -->
<span :class="{ 'is-disabled': disabled }" />

<!-- 3. 数组：把上面两种组合起来 -->
<span
  class="dot"
  :class="[
    `dot--${status}`,
    { 'is-disabled': disabled },
  ]"
/>
```

对应的 CSS：

```css
.dot { width: 8px; height: 8px; border-radius: 50%; }
.dot--success { background: #07c160; }
.dot--warning { background: #ff976a; }
.dot--error   { background: #ee0a24; }
.dot.is-disabled { opacity: 0.4; }
```

`class` 和 `:class` 可以**同时写**，Vue 会自动合并。固定的类名放 `class`，会变的放 `:class`，读起来最清楚。

### 新手最常踩

**1. 反引号写成了单引号**

```vue
<span :class="'dot--${status}'" />   <!-- 错 -->
<span :class="`dot--${status}`" />   <!-- 对 -->
```

写错的话，类名**真的**就叫 `dot--${status}` 这九个字符，CSS 当然匹配不上。

键盘上反引号在 `Esc` 下面、数字 `1` 左边。这是练习 1「故意改坏」第二条。

**2. 类名拼对了，但 CSS 里没这条规则**

`dot--warning` 生成得没问题，但你 CSS 只写了 `success` 和 `error` —— 照样没颜色。F12 看元素 class 存在、却没有任何样式命中时，就是这个情况。

**3. 对象写法的 key 带连字符要加引号**

```vue
:class="{ is-disabled: disabled }"     <!-- JS 语法错误 -->
:class="{ 'is-disabled': disabled }"   <!-- 对 -->
```

## 禁用状态

### 是什么

`disabled` 不是一个样式，是**三件事**：

1. **看起来**不能用 —— 变灰、鼠标变成禁止符号
2. **真的**不能用 —— 事件处理里判断，禁用时直接 `return`
3. 如果底层是原生表单元素，**把原生属性传下去** —— `:disabled="disabled"`

### 不做全三层会怎样

只做第 1 层（变灰）的话：用户照样能点，照样触发事件，照样改数据。这叫"看起来禁用"。

[速查表](Vue组件速查表.md)的提交前检查里那条「disabled 不只是变灰」说的就是这个，它是代码审查里最常被打回的问题之一。

### 最小写法

```vue
<script setup lang="ts">
interface Props {
  disabled?: boolean
}

const props = withDefaults(defineProps<Props>(), {
  disabled: false,
})

const emit = defineEmits<{
  click: [event: MouseEvent]
}>()

function handleClick(event: MouseEvent) {
  if (props.disabled) return
  emit('click', event)
}
</script>

<template>
  <button
    class="app-button"
    :class="{ 'is-disabled': disabled }"
    :disabled="disabled"
    @click="handleClick"
  >
    <slot />
  </button>
</template>
```

三层分别在：

- 第 1 层 → `:class="{ 'is-disabled': disabled }"` 配合 CSS
- 第 2 层 → `handleClick` 里的 `if (props.disabled) return`
- 第 3 层 → `:disabled="disabled"`

### 新手最常踩

**1. 用 `<div>` 当按钮**

`<div>` 没有原生 `disabled` 属性，第 3 层做不了，只能靠第 2 层拦。这也是"能用 `<button>` 就别用 `<div>`"的理由之一（另一个理由是键盘和读屏软件）。

**2. 以为 CSS 的 `pointer-events: none` 就够了**

它只拦鼠标。键盘回车、代码里直接调用、测试脚本触发，全都照样生效。

**3. 删掉第 2 层**

练习 3「故意改坏」第二条就是这个：删掉 `if (props.disabled) return`，然后观察禁用按钮为什么还在加数。

## 受控组件

### 是什么

组件自己**不存**值。值从父组件来（props 进），用户一改就立刻报给父组件（emit 出）。

**父组件是唯一的真相来源。**

反过来，组件自己用 `ref` 存一份值、父组件不插手的，叫非受控。

### 怎么选

问自己：**这个值父组件需要知道吗？需要能从外部改吗？**

| | 受控 | 非受控 |
|---|---|---|
| 值存在哪 | 父组件 | 组件自己 |
| 怎么实现 | props 进 + emit 出（通常用 v-model） | 内部 `ref` |
| 练习里的例子 | BaseSwitch、BaseInput | CountButton 的 `count` |

练习 3 的 `CountButton` 把 `count` 存在组件内部，是因为"点了几次"这件事父组件不需要掌控，它只要在变化时被通知一声（所以才有 `change` 事件带参数）。

### 不理解它会怎样

你会写出这两类 bug，而且不知道该往哪查：

- 输入框里能打字，但父组件的值不变（只改了界面，没报上去）
- 父组件改了值，输入框不跟着变（界面读的是本地那份，没读 props）

### 最小写法

```vue
<input :value="props.modelValue" @input="onInput" />
```

值**永远**来自 props，`@input` 只负责往上报。注意这里**没有**把用户输入存进本地 `ref`。

### 新手最常踩

**1. 两份真相**

既用 props，又在本地 `ref` 存一份，然后在各处手动同步。这是最常见的写法，也是最容易出不一致的写法。

```ts
// 不要这样
const localValue = ref(props.modelValue)
```

**2. 受控组件忘了 emit**

打不进字。见 [v-model 第 3 条](#v-model)。

**3. 该受控的做成了非受控**

练习 6A 的完成标准第 2、3 条就在验这个：

- "父组件中的值会随输入变化" → 验你 emit 了
- "外部修改值时，输入框也会更新" → 验你读的是 props，不是本地副本

## 二次封装

### 是什么

在别人的组件（或原生标签）外面，包一层自己的组件。

### 为什么要包

公司全站按钮要统一圆角、主色、字号。

不包的话，100 个页面里各写一遍：

```vue
<van-button type="primary" round size="large">保存</van-button>
```

改一次设计稿要改 100 处，而且总有人漏写某个属性，页面之间长得不一样。

包成一层之后：

```vue
<AppButton variant="primary">保存</AppButton>
```

样式决策收敛到一个文件里，改一处全站生效。

### 包的时候三样东西别丢

这是练习 7 的核心：

| 要透传的 | 怎么做 | 丢了会怎样 |
|---|---|---|
| 属性 | [`v-bind="$attrs"`](#attrs-透传) | `<AppButton id="save">` 页面上找不到这个 id，测试脚本定位不到元素 |
| 插槽 | `<slot />` | `<AppButton>保存</AppButton>` 显示成空白按钮 |
| 事件 | 原生事件会自动跟着 `$attrs` 走 | `@click` 不触发 |

### 新手最常踩

见 [$attrs 透传](#attrs-透传)。练习 7A 的完成标准"外部传入的属性能落到真正的 button 上"就是在验这件事。

## $attrs 透传

### 是什么

调用方传了、但你**没有**在 `defineProps` 里声明的那些属性，Vue 全收在 `$attrs` 里。

```vue
<AppButton variant="primary" id="save" aria-label="保存" />
```

`variant` 你声明了，是 prop。`id` 和 `aria-label` 你没声明，进 `$attrs`。

### 默认行为

Vue 会自动把 `$attrs` 放到你模板的**根元素**上。

所以模板只有一个根元素时，你什么都不用做，透传就已经生效了。

### 什么时候需要手动管

当根元素不是你想要的目标时。比如外面包了一层 `<div class="wrapper">`，里面才是真正的 `<button>`：

```vue
<template>
  <div class="wrapper">
    <button>
      <slot />
    </button>
  </div>
</template>
```

这时 `id="save"` 会落到 `wrapper` 这个 div 上，不是 button 上。需要手动接管：

```ts
defineOptions({ inheritAttrs: false })
```

```vue
<template>
  <div class="wrapper">
    <button v-bind="$attrs">
      <slot />
    </button>
  </div>
</template>
```

`inheritAttrs: false` 的意思**不是**"不透传"，是"**别自动放，我自己放**"。

这正是练习 7B 让你去公司代码里找答案的那个问题：为什么 `VanButton` 的封装要写 `inheritAttrs: false`。

### 新手最常踩

**1. 关了自动放置，却忘了手动放**

```ts
defineOptions({ inheritAttrs: false })
```

模板里没有任何 `v-bind="$attrs"` → 所有外部属性**彻底消失**，而且不报错。

**2. 两个地方都 `v-bind="$attrs"`**

同一个 `id` 在页面上出现两次，`document.getElementById` 的行为就不可预测了。

**3. 以为声明过的 prop 也在 `$attrs` 里**

不在。声明了就是你的 prop，`$attrs` 只装"你没要的那些"。所以 `v-bind="$attrs"` 不会把 `variant` 当成 HTML 属性糊到 button 上。

## 原生 input

### 是什么

`<input>` 是原生标签，不是 Vue 组件。它**没有** `modelValue` 这个概念。

它的两半是 `:value` 和 `@input`。

### 最小写法

```vue
<script setup lang="ts">
const props = defineProps<{ modelValue: string }>()

const emit = defineEmits<{
  'update:modelValue': [value: string]
}>()

function onInput(event: Event) {
  const value = (event.target as HTMLInputElement).value
  emit('update:modelValue', value)
}
</script>

<template>
  <input
    :value="props.modelValue"
    @input="onInput"
  />
</template>
```

### 那个 `as HTMLInputElement` 是干什么的

`event.target` 是"被操作的那个 DOM 元素"。TypeScript 不知道它一定是个 `<input>`（理论上可能是任何元素），所以不让你直接读 `.value`。

`as HTMLInputElement` 就是你告诉 TS："我确定这是个 input，放心读。"

这就是 [02 里 TypeScript 三种写法](02-Vue组件必会知识.md#typescript-先学三种写法)的第三种在实际代码里的用处。

### 新手最常踩

**1. 在 input 上写 `v-model="props.modelValue"`**

等于想直接修改 props，报错。原生 input 的 `v-model` 要求一个可写的变量，props 不是。

**2. 用 `@change` 代替 `@input`**

- `@input` —— 每敲一个字就触发
- `@change` —— 只在失去焦点时触发

用 `@change` 的话，用户打字的过程中父组件拿不到值，练习 6A 的"输入内容能实时显示在父组件"就不满足。

**3. 清空时把值设成 `null`**

```ts
emit('update:modelValue', null)   // 输入框里会显示 "null" 四个字母
emit('update:modelValue', '')     // 对
```

练习 6B 的要求是"值变为空字符串"，就是在避这个坑。
