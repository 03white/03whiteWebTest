# Vue 业务组件学习台：设计说明

日期：2026-11-20

## 1. 目标与范围

新建独立项目 `vue-router-pinia-demo/`，帮助学习者通过可操作的页面和可读源码，理解 Vue Router、Pinia 与 Element Plus 业务组件封装如何配合。

用户已确认以下方案：Vue 3 + Vite + Vue Router + Pinia + Element Plus；JavaScript、Composition API、`<script setup>`；左侧导航与右侧内容布局；围绕用户管理的小业务组织示例。

成功标准不仅是页面能显示，还包括：用户能沿着 README 指定的路径理解“点击菜单 → 路由匹配 → 页面渲染”和“页面操作 → store action → 其他页面同步更新”。

### 包含

- 固定保留的应用布局、可折叠侧栏、菜单高亮、页面标题。
- 学习首页、用户管理、用户详情、收藏用户、组件示例五类页面。
- 动态路由、路由参数、查询参数、编程式导航、懒加载及不存在页面处理。
- Pinia 跨组件和跨页面状态共享、计算派生数据与 action。
- 在 Element Plus 基础上封装职责清晰的业务组件，演示 props、emit、v-model 和插槽。
- 本地模拟数据、中文关键注释、项目启动与源码阅读说明。
- 构建检查与主要交互验证。

### 不包含

后端服务、账号登录、权限控制、接口拦截器、通用低代码表单/表格引擎、图表，以及对现有项目的改造。

不修改 `component-demo/`、`vue3-admin-demo/` 及已有未提交文件。不自动提交或推送 Git 变更。

## 2. 技术与目录边界

使用 Vue 3、Vite、Vue Router、Pinia、Element Plus 和官方图标库。以 JavaScript 为主，不引入 TypeScript、额外 UI 库或复杂分层。

```text
vue-router-pinia-demo/
  README.md
  package.json
  index.html
  vite.config.js
  src/
    main.js
    App.vue
    styles/             全局布局及少量主题变量
    router/             路由配置
    layouts/            应用壳、侧栏与顶栏
    stores/             用户业务状态、侧栏状态
    data/               初始模拟用户数据
    components/
      common/           PageHeader
      business/         UserSearchForm、UserFormDialog、UserStatusTag
    views/              首页、用户列表、用户详情、收藏、组件示例、404
```

避免把所有逻辑塞进一个页面，也不为简单逻辑创建多层 service/repository。组件和文件名表达职责。

## 3. 布局与路由

桌面端为左侧导航、顶部标题栏、右侧主内容区。以清爽浅色管理界面为主，保留 Element Plus 熟悉的交互。窄屏下侧栏缩窄或转为可展开导航，内容区不因固定宽度溢出；表格允许内部横向滚动。

路由由一个布局父路由和子路由组成，`App.vue` 渲染顶层 `RouterView`，布局中的 `RouterView` 渲染具体业务页。各页面使用动态 import 懒加载。

| 路径 | 页面 | 行为 |
| --- | --- | --- |
| `/` | 入口 | 重定向到 `/home` |
| `/home` | 学习首页 | 介绍示例与源码阅读顺序，使用 RouterLink 跳转 |
| `/users` | 用户管理 | 搜索、分页、新增、编辑、收藏及进入详情 |
| `/users/:id` | 用户详情 | 用 useRoute 读取 ID，从 store 取用户；提供明确的返回列表按钮 |
| `/favorites` | 收藏用户 | 查看收藏与取消收藏，可进入用户详情 |
| `/components` | 组件示例 | 在独立示例中体验四个封装组件及其输入/输出 |
| 未匹配路径 | 404 | 显示未找到页面并提供返回首页入口 |

通过 `meta.title` 管理页面标题；侧栏菜单与路由配置关联，避免重复维护路径和标题。用户详情不是独立菜单项，但保持用户管理菜单高亮。详情中的无效或不存在 ID 显示“用户不存在”，不渲染空用户信息。

列表搜索条件与页码同步至 query，展示 `params` 与 `query` 的区别，并使详情返回列表时可恢复筛选。搜索、清空筛选和修改每页条数时重置页码；输入或外部 query 中不合法的页码使用安全默认值，超出范围时回到有效页。

## 4. 页面行为

### 学习首页

介绍布局、路由、状态管理和业务组件四个部分。提供通往用户管理、收藏用户及组件示例的入口；说明数据仅在当前运行会话中保留，刷新会恢复模拟数据。

### 用户管理

- 初始模拟用户包含稳定 ID、姓名、邮箱、部门、状态与创建日期。
- 支持姓名或邮箱关键词、状态筛选、查询、重置和分页。
- 新增与编辑复用 UserFormDialog；保存后更新 Pinia 中的用户列表。
- 新增用户使用稳定且不冲突的 ID；编辑保留 ID 和创建日期。
- 收藏按钮切换用户收藏状态；重复收藏不会产生重复记录。
- 点击查看进入动态详情路由，携带来源列表 query 以支持返回。
- 无匹配记录展示空状态。

### 用户详情

展示当前 ID 对应的用户及收藏操作，使用命名路由与参数跳转。页面解释 `useRoute` 用于读取路由信息、`useRouter` 用于发起导航。切换 ID 后详情响应更新，不保留旧记录。

### 收藏用户

展示由用户列表和收藏 ID 派生出来的收藏用户，不复制一份用户对象作为收藏数据。编辑用户后收藏页自动使用最新信息；取消收藏后侧栏数量和页面一起更新。没有收藏时提供前往列表的入口。

### 组件示例

每个封装组件有简短的用途说明、使用代码片段与可交互预览：

- PageHeader：展示操作插槽。
- UserStatusTag：展示不同业务状态对应的标签。
- UserSearchForm：展示 v-model 和查询/重置事件，回显当前条件。
- UserFormDialog：用局部示例数据演示打开、校验、提交与取消，不暗中修改正式用户列表。

## 5. Pinia 数据流

使用 Setup Store，以 `ref` 表达状态、`computed` 表达 getter、普通函数表达 action。页面通过 `storeToRefs` 解构响应式 state/getter，action 直接从 store 调用，并用注释说明区别。

### users store

- state：用户数组 `users`、收藏 ID 数组 `favoriteIds`。
- getter：`favoriteUsers`、`favoriteCount` 等必要派生数据。
- action：新增用户、更新用户、切换收藏。
- ID 一律使用统一的字符串类型，避免路由参数与数字 ID 比较失败。
- store 不保存某个页面的弹窗开关、表单草稿或搜索条件；这些属于页面局部状态或路由 query。

### app store

仅保存侧栏折叠状态与切换 action，展示布局组件之间共享 UI 状态的用途。

### 持久化约定

默认不使用 localStorage 或持久化插件，避免引入存储同步和迁移概念。页面切换期间状态保留，浏览器刷新后恢复模拟数据；首页与 README 明确说明此行为。后续学习时可以在此基础上单独添加持久化。

## 6. 业务组件契约

### PageHeader

- 输入：`title`、可选 `description`。
- 插槽：`actions` 放新增按钮等页面操作。
- 不读取路由、不访问 store，可以在任意页面使用。

### UserStatusTag

- 输入：`status`，业务取值为 `active` / `inactive`。
- 输出：统一的 Element Plus 标签颜色和“启用 / 停用”文案。
- 未知值显示中性“未知状态”，不误判为启用。

### UserSearchForm

- 输入/输出：`v-model` 绑定 `{ keyword, status }`；通过 `update:modelValue` 返回新的条件对象，不直接修改 props。
- 事件：`search` 携带当前条件，`reset` 表示清空并重新查询。
- 组件负责筛选控件和条件收集；页面负责筛选数据、更新 query 和分页。

### UserFormDialog

- 输入/输出：`v-model` 控制显示，`user` 为可选的待编辑用户；`submit` 提交校验后的表单数据。
- 内部：Element Plus Dialog + Form；姓名必填、邮箱必填且格式正确、部门必选、状态必选。
- 打开弹窗时从 user 创建本地草稿，新增时使用默认空值；编辑、取消均不直接修改用户对象。
- 取消不提交，重新打开恢复正确初始值并清除旧校验状态。
- 页面收到 submit 后调用 store action 并给出成功提示；组件本身不导入 store，也不执行路由跳转。

## 7. 错误与边界

- 页面不存在和用户不存在分别有可恢复的空状态。
- 搜索没有结果、收藏为空均提供明确反馈。
- 无效 query、分页越界、未知状态有安全处理。
- 保存前表单校验，不接受空姓名、无效邮箱；提交时去除姓名、邮箱等首尾空格。
- 不使用 v-html 渲染用户数据，示例代码按文本显示。
- 无实际网络请求，因此不伪装接口加载；必要时用按钮操作反馈明确结果。

## 8. 文档与验证

README 包含：环境与启动命令、技术栈、目录树、页面与知识点对照、推荐阅读顺序，以及“基础控件 / 业务组件 / 页面 / store”的职责边界。中文注释集中解释教学重点，不逐行重复代码。

验收项：

1. 安装依赖后能启动，生产构建通过。
2. 点击菜单、浏览器前进后退、直接访问详情和未知路径正常。
3. 搜索、重置和分页能协同工作，返回列表保留来源筛选。
4. 新增和编辑校验生效，取消不会修改 store，重新打开不残留表单草稿。
5. 收藏操作使列表、详情、收藏页和侧栏计数同步，重复操作无重复收藏。
6. 组件示例可独立操作，且不会意外修改用户管理数据。
7. 桌面与窄屏布局可用，浏览器无应用级控制台错误。
8. 对 store 和关键纯逻辑提供自动化测试，执行构建与测试并如实记录验证结果。

## 9. 设计取舍

围绕一个小业务串联知识点，而非完全分离的知识点页面，使数据流可以追踪。使用明确的业务组件而非万能组件，优先展示组合、输入输出和职责边界。使用 JavaScript 与本地数据，先把 Router 和 Pinia 学清楚，再考虑 TypeScript、接口与权限。
